# 弹幕姬 UI 风格设计准则

状态：0.8.14 候选设计（2026-09-12），提供九套皮肤，映像柔焦排第二。本文件是桌面端透明 OBS 输出窗口的实现依据；设置窗口不出现在 OBS 输出中，也不沿用弹幕皮肤。

## 风格词汇来源

- 本轮参考已实际读取的 [StyleKit 风格目录](https://www.stylekit.top/zh/styles) 与其[公开源码](https://github.com/AnxForever/stylekit)，机甲和彩漫分别以 `lib/styles/mecha.ts`、`lib/styles/comic-style.ts` 的说明及卡片构造为起点。
- 黑白手绘采用用户选定的 A 款：细线圆角对白框、左下曲线气泡尾、框内昵称；Windows 95 按用户指定的经典系统外观实现。风格参考需结合中文可读性、OBS 透明输出和低开销静态实现，不直接搬入整页装饰或交互动画。
- 控制台当前采用 Glassmorphism（玻璃态）中的磨砂玻璃材质，但提高承载面不透明度；不沿用弹幕“轻雾玻璃”的通透程度。

程序设置提供主界面深色／浅色双按钮与背景不透明度滑块（30–100%，默认深色、97%）。外观保存到独立的 `controlAppearance` 程序配置，不纳入弹幕皮肤或样式预设。只调整主窗口背景 alpha，文字和控件自身不整体淡化；浅色模式同步主界面、弹窗、表单与菜单，皮肤缩略图保持原皮肤外观。滑块拖动实时预览、合并保存，写盘失败恢复上次保存值并显示提示。

直播间连接按钮始终呈现可执行操作：已连接时为“断开连接”，连接／重连中为“取消连接”，未连接时为“连接”或“重新连接”。修改房间号后允许“切换直播间”，改回原值恢复当前状态的操作。主动断开停止接收、重连和待显示队列，保留已显示内容与 SC 计时，不关闭输出窗口；保存的房间号继续保留。请求处理期间防止重复提交，失败后恢复可用状态。

## 当前皮肤

用户提供的琥珀色 EL 屏照片用于确定 EL 皮肤的颜色与轻微发光质感；Outline Style 方向用于简洁描边；图片卡片截图用于确定映像柔焦的构图。原 UI Prompt 站访问不稳定，本轮以可读取的 StyleKit 内容和用户图片为依据。旧点阵、Risograph、黑白简报和暖纸札记不在当前皮肤列表中提供；Y2K、视觉小说、装饰艺术与赛博和风未采用。

| ID | 名称 | 视觉方向 |
| --- | --- | --- |
| glass | 轻雾玻璃 | 保留原有冷调透明承载面 |
| portrait | 映像柔焦 | 右侧头像或礼物图，模糊渐隐的图片承载面 |
| mecha | 机甲装甲 | 海军蓝装甲、军绿结构、警示黄切角 |
| comic | 彩色漫画 | 墨线气泡、蓝色昵称牌、黄红强调面 |
| manga | 黑白手绘 | 白底细线圆角对白、左下曲线气泡尾、框内昵称与灰阶手写文字 |
| win95 | Windows 95 | 灰色立体框、蓝色标题栏、白色正文区 |
| el | 琥珀 EL | 普通文字、琥珀微光、近黑屏幕 |
| tui | OpenCode TUI | 保留紧凑终端排版 |
| outline | 轻线描边 | 纯白文字与圆角白线、系统幼圆、独立阴影 |

九套均用普通 DOM 文字、CSS 与少量静态 SVG 实现，复用未变化消息卡片。不得加载专用点阵字体、字模解码、文字或表情 Canvas，也不下载远程字体。黑白手绘可按需加载随程序提供的静态轮廓字体。皮肤列表与共享配置注册表保持上表顺序。

首页每次打开默认折叠皮肤列表，只显示固定前两套 glass 和 portrait；点击卡片下方居中的双下箭头展开其余七套，展开后改为上箭头，点击收起恢复两套。展开状态只在当前窗口会话内保持，不保存为用户设置；选择其他皮肤不能自动展开或将其挤入前两位，折叠态必须显示当前选中的皮肤名称。

展开/收起控件采用卡片下方全宽、30 px 高的窄条，箭头始终水平居中，不显示右下角小字。当前隐藏皮肤的名称在独立一行居中显示，不与箭头共用横向空间。使用可键盘操作的原生按钮，保留 `title`、`aria-label`、`aria-expanded` 与关联容器 `aria-controls`，并随展开状态更新说明；隐藏选项不得保留在键盘焦点序列中。

## 1. 全局不可变规则

SC 固定区域按最新在上排列，避免旧 SC 堆满后新留言完全落在可见区外。该顺序不改动主进程的接收身份、金额计时或普通消息队列；普通弹幕进入时，未变的 SC 不能反复触发布局变更并中断普通卡片上移动画。下架最新 SC 后自然露出前一条。

### 1.1 透明输出

- OBS 输出窗口的页面底色必须是完全透明的 `rgba(0, 0, 0, 0)`。
- 禁止把应用窗口外框、控制台标题栏和设置 UI 放进 OBS。Windows 95 风格的卡片标题只承载该条消息的昵称、身份等信息，属于消息外观。
- 通常承载面不透明度为 0 时，底板、描边与分隔装饰透明；轻线描边例外，其“底色不透明度”只控制底色，纯白边框始终可见。玻璃与轻线的文字阴影另由独立强度控制。
- 设置窗口与输出窗口分离；调整设置不能被 OBS 窗口采集捕获。

### 1.2 稳定等宽准则

- 普通弹幕、礼物、SC 和系统提示共用同一个外部内容宽度。
- 消息区使用输出窗口的完整宽度，仅扣除当前皮肤设置的左右留白；每侧默认 8 px、范围 0–64 px，随整体比例缩放。
- 普通消息由底部向上排列，各套默认开启“仅显示完整卡片”，只绘制能完整放入可用高度的卡片，顶部不足一整张时整张隐藏。该皮肤取消勾选后允许顶部显示部分普通消息；尚在置顶的 SC 不受此开关影响，到期进入普通列表的 SC 则遵循同一规则。隐藏仅影响绘制，不压缩布局或删除历史；尺寸、字号、异步内容行高或 SC 占用变化后重算，空间恢复时重新显示。完全隐藏的映像柔焦卡片释放背景图层。
- 横向留白只由消息区统一提供，头像左边和时间右边不再叠加额外外侧间距；头像与正文的间隔、正文为时间预留的空间单独保留。
- 窄窗口按可用正文宽度限制实际左右留白，避免大留白将内容挤至零宽；不覆盖已保存的值，窗口拉宽后恢复所选留白。
- 所有条目的左右边界一致。不得为了强调礼物而缩窄卡片、纸条或文字区域。
- 普通弹幕内容默认左对齐；既有居中礼物排版保持。机甲、彩漫、黑白手绘和 Windows 95 的消息共用左对齐结构。
- 礼物通过配色、标签和适当增加上下留白区分，保持内容可读；不强制固定高度倍数或挤压正文。
- 新消息出现时不得引起已有条目横向跳动或宽度重排。

进房欢迎作为 type=welcome 的紧凑文本行进入普通消息列表，不再计时消失，也不再预留底部区域。欢迎与弹幕、礼物按接收顺序共同向上滚动，与到期 SC 共用最近 48 条普通消息历史，未到期 SC 继续独立置顶。每套皮肤独立保存开关、欢迎字号（默认 18 px，12–48 px，随整体比例缩放）及提示文字/昵称颜色；使用主题字体和该皮肤的紧凑承载面，不附加头像、元数据或另一套欢迎弹窗样式。长昵称自然换行。关闭期间不写入新的欢迎，已有欢迎在该皮肤下隐藏；重开可展示仍在历史内的欢迎。旧 welcomeGap 已移除，旧设置和预设缺 welcomeFont 时补默认字号，不重置其他设置。

### 1.3 信息层级

从高到低固定为：

1. 弹幕正文或礼物名称/数量。
2. 用户名。
3. 身份、陪伴时长、礼物人民币价值等元数据。
4. 时间戳和装饰性状态文本。

建议基线（允许随输出缩放等比调整）：

| 元素 | 建议字号 | 字重 | 说明 |
| --- | ---: | ---: | --- |
| 正文/礼物主体 | `20–26px` | `500–650` | 最大、最清晰 |
| 用户名 | `14–16px` | `500–600` | 次级重点 |
| 身份/陪伴/价值 | `12–13px` | `450–500` | 不抢正文 |
| 时间/装饰状态 | `11–13px` | `400–450` | 右下角或边角 |

### 1.3.1 九套皮肤默认设置基线

皮肤设置必须按皮肤分别保存，互不共享；输出窗口的尺寸和位置由桌面窗口统一保存。2026-09-10 按用户当前外观更新默认值，新用户输出窗口为 515 × 650 逻辑像素；升级不覆盖已保存的个人设置。当前默认值如下：

| 皮肤 | 整体比例 | 垂直间距 | 正文 | 用户名 | 元数据 | 时间 | 字体 | 承载面不透明度 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| 轻雾玻璃 | 100% | 10px | 26px | 16px | 13px | 12px | Microsoft YaHei UI | 28% |
| 映像柔焦 | 100% | 12px | 26px | 16px | 13px | 11px | Microsoft YaHei UI | 92% |
| 机甲装甲 | 100% | 10px | 26px | 16px | 12px | 11px | Microsoft YaHei UI | 100% |
| 彩色漫画 | 100% | 12px | 26px | 16px | 12px | 11px | Microsoft YaHei UI | 100% |
| 黑白手绘 | 100% | 12px | 26px | 16px | 12px | 11px | ZCOOL KuaiLe | 100% |
| Windows 95 | 100% | 12px | 26px | 16px | 12px | 11px | Microsoft YaHei UI | 100% |
| 琥珀 EL | 100% | 6px | 26px | 16px | 12px | 12px | Cascadia Mono | 100% |
| OpenCode TUI | 100% | 2px | 20px | 14px | 12px | 13px | JetBrains Maple Mono | 70% |
| 轻线描边 | 100% | 8px | 26px | 16px | 12px | 12px | YouYuan（系统幼圆） | 18% |

默认值唯一代码来源为 desktop/themes.js，由主进程、控制台与输出共用。九套皮肤默认左右留白均为 8 px，进房欢迎开启、欢迎字号 18 px。玻璃、轻线描边、机甲、彩漫和 Windows 95 默认显示头像；EL、TUI、映像柔焦与黑白手绘默认关闭头像。黑白手绘的旧设置和预设若明确保存 showAvatar:true，必须保留该选择。所有字体可编辑；除黑白手绘按需使用内置 ZCOOL KuaiLe 外，默认使用系统字体，缺字和未安装字体正常回退，不联网下载字体。

九套皮肤均保存独立 `emoteScale`，范围 50–200，默认 100。设置中的“表情大小”百分比滑块放在正文字号旁，按当前编辑皮肤实时预览和保存，不改文字字号；渲染使用 `--emote-scale` 将原有普通与官方表情尺寸乘以所选比例，不增加图片资源或渲染引擎。恢复默认回到 100，旧设置及旧预设缺字段补 100；严格预设校验拒绝非数值、非有限值及越界值，普通设置归一化将越界数值限制在范围内。

九套皮肤均保存独立 `fullCardsOnly`，默认 true。勾选框“仅显示完整卡片”放在皮肤设置中，控件 `fullCardsOnlyInput` 读写当前编辑皮肤；取消后顶部可显示半张或部分普通消息，不改变逐条出场与上移动画，也不改变 SC 置顶。支持实时预览、保存、恢复默认及样式预设，旧配置和旧预设缺字段补 true，明确 false 必须保留；严格预设校验拒绝非布尔值，普通设置中非法值回到默认 true。

升级将旧 pixel 替换为 el，旧 mono、risograph 和 paper 替换为 glass，采用替代皮肤默认外观；旧预设保留 ID、名称、输出尺寸，不删除用户预设。已保存的 glass 配置优先于旧别名，其他保留皮肤的有效自定义与非视觉状态不变。旧 mono 不映射到新 manga。移除字库引擎字段，并替换残留的专用点阵字体名。

轻雾玻璃独立提供承载面颜色，默认黑色 `#000000`，与不透明度共同生效，并随样式预设保存。该选项只在玻璃皮肤设置中显示；其他皮肤保留各自的底板与纹理。旧玻璃设置及预设缺少颜色字段时沿用黑色。

`shadowStrength` 只在 glass 与 outline 的配置和预设中保存，范围 0–100，默认分别 60 和 70；缺失时补各自默认值，显式 0 不得被默认值覆盖。预设中非数值、非有限值或越界值拒绝，其他七套皮肤忽略该额外字段。设置滑块只在这两套皮肤出现，支持实时预览、保存、恢复默认和预设切换；0 时关闭本次新增的阴影效果，不影响原有字体颜色。

outline 默认所有文字颜色字段均为 `#ffffff`，默认字体为 `YouYuan`。`outlineStyleVersion: 1` 是该皮肤专用的一次性迁移标记；旧设置与旧预设尚无标记时，只将各字段恰好等于其原默认值的灰蓝颜色改白，将旧默认 `Microsoft YaHei UI` 改为 `YouYuan`。自定义颜色、字体、字号、尺寸、透明度与头像选择保留，预设名称和 ID 不变。迁移后用户可选回旧色值或微软雅黑，新标记防止再次自动替换；玻璃完全不参与这项配色和字体迁移。

进房欢迎的提示文字与昵称分别提供独立颜色设置，位于该皮肤的欢迎分组内。缺少独立颜色时沿用时间颜色及正文颜色，之后不再随其他字段的颜色编辑而改变。

首页的样式预设保存当前皮肤的完整外观配置、表情大小、完整卡片显示选择、SC 永久置顶选择和输出尺寸；套用不修改其他皮肤及房间、登录、位置、置顶、穿透等非皮肤状态。命名、改名、覆盖和删除使用与控制台一致的弹窗与下拉菜单，不使用系统确认框；删除先明确提示，再由用户确认。

黑白手绘统一采用选定的圆角对白轮廓，不再提供形状选项，也不保存 `mangaShape`。旧设置和预设中的 `panel`／`oval` 等形状值直接忽略，其余字体、颜色、字号、头像、欢迎和输出尺寸保持；旧预设名称与 ID 不变，不因形状字段废弃而丢失预设。

- 时间戳固定在当前条目的右下角，不建立独立时间列。
- 相同字段在不同身份之间必须使用完全相同的字号、字重、行高和间距。
- 禁止用更大字号表示主播、房管或舰队等级。

### 1.4 身份表达

必须明确区分：`主播`、`房管`、`总督`、`提督`、`舰长`、`普通观众`。

- 身份差异只通过明确文字标签、克制的语义色和小型符号表达。
- 标签采用 `[主播]`、`[房管]`、`[总督]`、`[提督]`、`[舰长]`；普通观众标签可隐藏，但数据结构中仍保留。
- 不改变对应字段的字号、字重或整体宽度。
- 颜色必须保证在动态游戏画面上仍可辨识；正文始终优先使用高对比中性色。

建议语义色：

| 身份 | 基础语义色 |
| --- | --- |
| 主播 | 克制珊瑚粉 |
| 房管 | 冷蓝/青蓝 |
| 总督 | 珊瑚红 |
| 提督 | 低饱和紫 |
| 舰长 | 天青/浅蓝 |
| 普通观众 | 中性白或皮肤主墨色 |

每套皮肤可以把这些语义映射到自己的有限色板，但不能依赖颜色作为唯一标识。

### 1.5 礼物与 SC

- 礼物条与普通弹幕严格等宽，对齐方式遵守对应皮肤的统一布局，内部仍维持清晰的名称—动作—数量层级。
- 礼物金额只读取既有协议和金额换算结果；UI 不引入新的换算逻辑或可配置比例。
- 人民币统一格式为 `￥ 30.00`，保留两位小数。
- SC 也保持同宽，通过更高行高、独立置顶、色彩或局部材质区分，不改变宽度；置顶时长由当前皮肤的计时选择决定，到期后进入普通列表并保留 SC 样式。
- 礼物和 SC 不得导致列表横向抖动。
- 桌面置顶 SC 卡片及其子元素必须排除在原生窗口拖动区域之外，独立接收横向滑动；下架后的 SC、普通消息与空白处支持移动窗口。鼠标穿透开启时应先解除穿透。
- 尺寸锁定只拦截用户缩放，不能阻止 SC 滑动或窗口移动。桌面置顶 SC 用整卡近透明鼠标接收层覆盖文字和空白区域，避免透明像素穿过输入；该层不进入 OBS。
- 只有达到滑动阈值并正常结束的手势可以下架 SC，桌面与 OBS 同步取消置顶并回到原接收位置。未达阈值、pointercancel 或丢失指针捕获应恢复原位，不意外下架、不遗留偏移。下架依靠共享场景更新，不用延迟 row.remove 删除本地节点；到期与滑动同时发生时不能污染已经归入普通流的卡片。
- 桌面预览关闭、隐藏或最小化时，新 SC 使用系统通知；通知不可用时尝试托盘气泡。短时间内多条 SC 可合并计数，避免逐条堆积提示。通知不创建预览、不清除 SC，点击后才打开或恢复桌面窗口并解除穿透，便于处理当前留言。
- 程序运行期间，实时通知横幅与 Windows 通知中心中仍有效的 SC 通知都必须支持点击打开桌面预览。横幅收起不等于通知失效；不得仅因收到通知 `close` 事件就移除点击监听或丢弃当前通知句柄。最多保留最新一条通知，SC 到期、手动下架、清除、旧通知被替换或程序退出时主动关闭并释放对应句柄及监听；通知不恢复已删除的 SC。
- 系统通知位于桌面系统区域，不得在 OBS 消息画布中加入通知弹框；已可见的桌面预览不重复通知。

“SC永久置顶”放在各套皮肤设置中，移除首页单独“消息显示”分组。每套 `themeConfigs[id].scNeverExpire` 默认 false，仅布尔 true 表示永久置顶；UI 读写正在编辑的皮肤，桌面和 OBS 应用当前选中皮肤的已保存值。打开皮肤编辑器仍按现有行为选中该皮肤。切换到计时皮肤时依据原收到时刻重算，已到期或手动下架的 SC 不重新置顶。

旧全局 `settings.scNeverExpire === true` 只迁移到缺少每套字段的配置，已明确为 true 或 false 的皮肤选择优先；旧全局关闭或缺省时缺字段补 false。归一化后删除旧全局字段，只保留每套配置。新样式预设保存 SC 选择，旧预设缺字段补 false；套用只改变目标皮肤的选择。开关立即提交完整设置，保存中暂时禁用开关和恢复默认，失败还原对应皮肤并在旁简短提示；后续外观保存应等待该提交结束，避免失败值被旧快照写回。

默认计时按金额使用以下节点，中间线性插值：

| 金额（元） | 停留时长（秒） |
| ---: | ---: |
| 2 | 5 |
| 30 | 60 |
| 50 | 120 |
| 100 | 300 |
| 500 | 1,800 |
| 1,000 | 3,600 |
| 2,000 | 7,200 |

低于 2 元至少 5 秒，金额缺失或非有限时按 60 秒，高于 2,000 元延伸最后一段比例。计时从本机实际收到 SC 时开始，不采用上游时间戳，补包不重置起点。勾选只永久置顶当前仍在置顶区的 SC；取消后按原接收时刻重算，已经超时则立即取消置顶。到期或手动下架通过 `scPinned:false` 保留 `type:sc`、金额、内容、头像、原 ID 和原时间，按最初接收序号归入普通历史，不能按上游时间戳或到期时间重新排为最新。下架 SC 计入普通 48 条上限，太旧的自然淘汰，不扩张历史；普通待显示队列的数量、节奏和顺序不被下架操作改变。补包、金额修正、重开输出和切换皮肤均不能重新置顶；上游撤回和清空仍真正删除。桌面与 OBS 使用相同到期结果，普通队列不延迟 SC 入场。归入普通列表的 SC 保留金额样式，移除手势与专用鼠标接收层，参与普通裁切、可见图片释放与后续上移动画；重复下架不删除该卡片。手动下架取消金额计时与关联通知，诊断以 unpinned 记录，expired 表示计时下架，removed 只表示上游实际删除。

### 1.6 动效

- 普通弹幕、礼物与欢迎由主进程统一排队，逐条安排出场；待显示队列与最近 48 条已出场历史分别保留，不能把一次突发消息先全部写入 48 条历史再丢掉尚未出场内容。
- 新消息进入时，已有卡片从旧位置平滑移动到新位置，新卡片从消息区下方进入，水平位移为 `0`；经过消息区边界时按该皮肤“仅显示完整卡片”的选择显隐或裁切。开关不改变动画与消息排序；不允许整卡缩放弹跳、连续积累动画或为每个输出端分别建立消息排序。
- 短时积压时加快出场节奏；持续高流量受待显示条数与字节上限保护，允许记录并跳过超限消息，不承诺无限缓存或每条都具备足够阅读时间。
- SC 不等待普通消息队列，即时加入置顶场景。已有卡片更新、清空、页面首次恢复和尺寸重排须避免错误重播入场动画。
- SC 置顶：只改变纵向位置和层级，宽度保持不变。
- 所有皮肤尊重系统“减少动态效果”设置。

### 1.7 播放状态

控制台连接状态旁提供轻量文字反馈：正常空闲隐藏；有积压时显示“待显示 N 条”，发生上限保护后显示“积压保护已跳过 N 条”。跳过计数属于当前场景，清空或换房时归零。提示不写入 OBS 卡片，也不改变弹幕正文或名单。

控制台启动时读取 `getWindowState.playback`，随后只订阅 `desktop:playback-changed` 事件；没有前端定时轮询。无桌面或 OBS 输出页订阅时，不保留旧待播队列和无意义的播放计时器，只维护有限最近消息；恢复输出后显示当前场景，不补播全部无人订阅期间的消息。

## 2. 轻雾玻璃 `light-fog-glass`

### 视觉目标

几乎透明、冷调、局部轻雾。材质只负责保证文字可读，不应被观众先注意到。

### 材质

- 无边框、无侧边彩条、无应用级磨砂。
- 条目使用同宽的局部冷色雾层；基础透明度建议 `0.05–0.10`。
- `backdrop-filter: blur(18px) saturate(110%)` 可作为起点，最终强度由用户调节。
- 圆角 `8–12px`，禁止过度药丸化。
- 阴影只允许极弱的黑色环境阴影，不能形成悬浮卡片感。
- 文字阴影可通过该皮肤“阴影强度”单独调整，默认 60，设为 0 时关闭；不得因此改写玻璃的原有字体或配色。
- 色温保持中性偏冷；禁止暖金、米黄或浓厚奶油色雾层。

### 排版与颜色

- 推荐字体：`MiSans, HarmonyOS Sans SC, Microsoft YaHei UI, sans-serif`。
- 正文近白；用户名使用低饱和身份色；元数据为冷灰。
- 礼物主体可使用低饱和灰粉，但“赠送”等动作词保持近白。
- 普通内容左对齐；礼物在同宽雾层内居中且增加垂直留白。

## 3. 琥珀 EL（el）

使用 #0e1110 近黑屏幕底和 #ffd479 琥珀色正文，名字与元数据通过亮度区分。普通系统字体与中文回退保持清晰，只保留小范围静态文字阴影；头像默认关闭，开启后按普通图像显示。

没有字模、像素网格、Canvas、表情栅格化或扫描动画。长中文自然换行，身份标签、礼物与 SC 沿用共用布局；欢迎仅共享字体与颜色，不另设框。

## 4. OpenCode TUI `opencode-tui`

### 视觉目标

参考真实 OpenCode 左侧界面：纯黑、平面、信息密度高，依靠排版、留白和少量终端色建立层级。明确排除暖棕透明 Kitty 终端风格。

### 字体与表面

- 首选：`JetBrains Maple Mono`。
- 回退：`Maple Mono NF CN, JetBrains Mono, Noto Sans Mono CJK SC, Microsoft YaHei UI, monospace`。
- 条目为中性黑/炭黑哑光表面，建议 `rgba(10, 10, 10, 0.92–0.96)`。
- 圆角 `2–4px`；无边框、无阴影、无磨砂。
- 开启头像时保持干净的头像边缘，不绘制原有蓝色描边。
- 主文字 `#F3F1EE`，元数据 `#9B9998`，状态橙 `#F1A431`，动作蓝 `#4FA8F5`，成功绿 `#76D88F`，礼物/主播珊瑚 `#EE8D96`。

### `Thought` 行

`+ Thought: xxx` 保留，但重新定义为“当前弹幕与上一条已接收弹幕之间的时间差”，纯属显示层信息。

- `< 1s`：显示整数毫秒，如 `+ Thought: 451ms`。
- `1s–59.9s`：显示最多一位小数，如 `+ Thought: 1.8s`；整数秒可显示 `12s`。
- `>= 60s`：显示 `1m 10s`。
- 第一条消息没有上一条记录时隐藏该行。
- 计算不得参与协议解析、排序或重连判断，不能延迟消息处理。

### 礼物身份与价值行

- 删除模型和构建语义；不得显示 `Build`、`DeepSeek V4 Flash` 或推理耗时。
- 用户名、身份与礼物价值必须位于同一行，例如：`云水之间 [舰长]    ▣ Gift · ￥ 30.00`。
- 使用 OpenCode 动作语义展示现有换算结果：`▣ Gift · ￥ 30.00`，但不得单独占用一行。
- 金额行为是正文的辅助信息，字号不超过用户名。
- 下一行只展示主要礼物信息：`赠送  小花花 × 10`。
- 礼物条与普通条同宽，内部整体居中，总高度约为普通条的 `1.35` 倍。

## 5. 卡片皮肤

### 轻线描边（outline）

透明画布搭配纯白细线圆角卡片，底色很淡。正文、昵称、身份、礼物、时间和欢迎的默认文字全部纯白，允许用户继续自定义颜色。头像采用方圆角，所有消息外部同宽，边框内间距在窄窗口自动收紧；欢迎作为流内文本行融入主题。

默认调用系统 `YouYuan`（幼圆），形成圆润中文笔画。通过 `font-synthesis-weight:none` 禁止模拟不存在的粗体，避免“问”等字在幼圆合成加粗时出现灰色、空心笔画；用户选择具备真实粗体的字体时仍按原字重使用真实粗体。原有颜色及阴影不变。此字体不是用户参考图片原字体的识别结果，也不作为资源随程序分发；未安装时回退微软雅黑或系统中文字体，不能保证跨电脑字形完全一致。

设置中的“底色不透明度”只控制卡片底色，纯白描边不随该值衰减；0 时仍保留文字和白线。“阴影强度”独立控制文字和边框阴影，默认 70，范围 0–100，0 关闭。该效果只用静态 CSS 阴影，不新增字体下载、Canvas 或持续绘制循环。

### 映像柔焦（portrait）

以用户提供的图片卡片为参考：每条消息的图片靠右，向左通过同源模糊色彩与透明渐变衔接。普通弹幕、SC 和欢迎用发送者头像；礼物用礼物图片，失败回退头像再到深色底。头像焦点图以 `portraitWidth` 控制占卡片宽度的比例（30–70%，默认48%），height:100%、cover居中铺满，允许适当裁切来维持主体大小；数值越大，头像越大、裁切越多。渐变在自身宽度25%处半显、57%处完全显现；整卡模糊底层继续cover铺满。礼物焦点图保持58%宽、contain居中和原有渐变；承载面不透明度控制整层图片，正文独立。

“头像占比”仅在映像柔焦设置显示并保存，支持实时预览、重置和样式预设，旧配置与预设缺值补48%；其他皮肤不保存该字段。调节只改变背景图片构图，不改变卡片尺寸、文字布局、图片来源或加载数量。

普通卡片至少 132 px 高、8 px 圆角，姓名、正文左对齐，右下角时间。欢迎仍是向上滚动的消息，此皮肤以紧凑的 52 px 图片条承载，继承单独的欢迎字号与颜色。默认不另放左侧小头像，可在设置中开启。

右下角时间保持用户选定的颜色与字号、原字重，以及原有78%不透明度的半透明质感；只补独立的深色文字阴影提高浅色背景上的可读性。阴影按整体比例缩放，独立于图片承载面透明度；不添加额外底框，也不改动时间位置或头像裁切规则。

只使用普通 img 和静态 CSS blur/mask/gradient，不提取像素或用 Canvas。仅该皮肤可见卡片启用观察与图片工作队列，最多四个加载任务；离屏释放图层，切回其他皮肤或透明度为零时断开观察并取消任务。礼物目录懒加载，按房间合并并发请求，缓存数量与有效期均有上限。其他皮肤保留原来表现。

`INTERACT_WORD_V2` 进房消息从已核实的 protobuf `uinfo.base.face`（22→2→2）读取头像，并与原包顶层 UID/昵称一起传给欢迎卡片。无效头像只触发已有缺图回退，不能丢弃有效欢迎；不能以 JSON 同名字段覆盖 protobuf 身份。

### 机甲装甲（mecha）

海军蓝 `#1a2744` 装甲面、军绿结构框和警示黄边缘切角建立机械感；正文默认亮白，礼物金额和重点使用警示黄，时间保持灰白。切角只施加在装饰层，完整卡片的布局框与桌面 SC 命中区域不被裁掉。普通弹幕、礼物、SC 和紧凑欢迎沿用同一套装甲结构，不添加假编号、状态灯、扫描线或动画仪表。

### 彩色漫画（comic）

使用完整闭合的粗墨气泡轮廓，圆角框与左下曲线尾巴由同一条 SVG 路径绘制，不能以圆角矩形和独立三角拼接。静态九宫格伸缩保留边角与尾巴结构，普通弹幕、礼物、SC 和最矮欢迎均使用完整轮廓。普通消息白底黑字、蓝色昵称牌白字；SC 使用黄色卡片，礼物使用红色金额牌。身份保留明确文字标签，自定义昵称、正文、礼物和欢迎颜色继续生效。卡片整体不旋转，不使用网点、爆炸框、拟声词、持续抖动、缩放或 Canvas。

### 黑白手绘（manga）

采用 A 款细线圆角对白：白色承载面以一圈连贯的细墨线包围，左下接自然弯曲的气泡尾。昵称、身份和正文均在气泡内，保持清楚的大小层级与左对齐，不再使用外置昵称牌、双线方条或椭圆框。轮廓由小型静态 SVG 表达，文字仍是正常 DOM，不栅格化成图片。普通弹幕、礼物、SC 与欢迎保持统一；全部默认文字颜色为灰阶。新用户默认关闭头像，旧显式开启选择保留；开启后显示原色，不对头像施加灰阶滤镜。原有字体、配色和字号可继续调整。

字体默认 `ZCOOL KuaiLe`，采用原字体静态轮廓产生不规则手写笔画，按其单一字重 400 排版，不用假粗体或文字阴影伪造手写。完整本地 WOFF2 为 871,928 字节、7,055 字形，覆盖全部 6,763 个 GB2312 汉字；没有删成仅覆盖演示消息的字集，缺字由系统字体回退。字体授权为 SIL OFL 1.1，来源和授权保存在 `desktop/fonts/zcool-kuaile/`。

只有当前皮肤为 manga 且字体设置实际选择 `ZCOOL KuaiLe` 时才懒加载本地字体；其他皮肤不注册或请求它，切换为本机字体时不启动该资源。不得增加远程字体、字模解码、字符 Canvas 或持续绘制循环。字体文件大小不能当作运行时内存用量。

### Windows 95（win95）

采用经典 `#c0c0c0` 灰色面板和明暗边线模拟立体边框；深蓝 `#000080` 标题栏承载默认白色昵称与身份，白色正文区域使用黑字。礼物金额、时间和欢迎用相同的凹凸面板语言，仍保持原有字号、配色、头像、欢迎和透明度控制。

使用普通系统中文字体，边框和阴影为静态 CSS。仅仿制外观，不生成操作系统窗口，也不添加没有功能的关闭、最小化、菜单或任务栏按钮。承载面不透明度为 0 时，所有标题底色、边线和面板装饰随之透明。

## 6. 实现与验收清单

- OBS 画布外部完全透明，没有窗口或设置面板轮廓。
- 九套皮肤按规定顺序显示，切换只改变视觉样式，不改变协议、排序、身份识别和金额逻辑。
- 普通弹幕、礼物和 SC 的外部宽度完全一致。
- 礼物通过对应皮肤的颜色、标签和留白区分，不改变外部宽度。
- 正文永远比用户名大；用户名永远比元数据醒目。
- 不同身份的对应字段字号和字重完全一致。
- 时间位于条目右下角，不形成高注意力时间列。
- 九套皮肤均没有点阵字库请求、字形 Canvas 或像素专用监听器，安装包不包含已移除资源。新手写字体是有独立 OFL 授权的静态轮廓字体，仅按需用于 manga。旧名称仅用于迁移；登录二维码库和未在桌面/OBS 加载的旧网页特效不属于点阵残留，不以关键字误删必要功能。
- TUI 不含模型名或 Build 文案；用户名/身份与 `￥` 总价同行。
- 九套皮肤以同一组中文长消息、表情、礼物、SC 与欢迎截图验收，检查窄窗口与关闭承载面的效果；manga 检查细线圆角、曲线尾与框内昵称在长短消息下的完整性。
- 验证旧皮肤/预设迁移、重启持久化、热切换与密集消息；有限样本的资源结果不能当成所有低配电脑的性能保证。
