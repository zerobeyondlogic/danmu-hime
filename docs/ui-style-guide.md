# 弹幕姬 UI 风格设计准则

状态：视觉基线已锁定（2026-08-11）。本文件是桌面端透明 OBS 输出窗口的实现依据；设置窗口不出现在 OBS 输出中，也不沿用弹幕皮肤。

## 风格词汇来源

- 统一以 https://www.uiprompt.site/zh/styles 作为 UI 风格名称与 AI 提示词参考。
- 用户使用站内风格词汇时，先查阅对应提示词，再结合弹幕可读性、OBS 透明输出和控制台可操作性做克制化适配。
- 控制台当前采用 Glassmorphism（玻璃态）中的磨砂玻璃材质，但提高承载面不透明度；不沿用弹幕“轻雾玻璃”的通透程度。

## 1. 全局不可变规则

### 1.1 透明输出

- OBS 输出窗口的页面底色必须是完全透明的 `rgba(0, 0, 0, 0)`。
- 禁止应用级外框、全局磨砂层、整块半透明矩形、标题栏和设置 UI。
- 只有弹幕条、礼物条、SC 等观众可见内容可以拥有局部承载面。
- 设置窗口与输出窗口分离；调整设置不能被 OBS 窗口采集捕获。

### 1.2 稳定等宽准则

- 普通弹幕、礼物、SC 和系统提示共用同一个外部内容宽度。
- 推荐基线：`--message-width: min(860px, calc(100vw - 64px))`。
- 所有条目的左右边界一致。不得为了强调礼物而缩窄卡片、纸条或文字区域。
- 普通弹幕内容左对齐；礼物内容在同宽容器内水平居中。
- 礼物通过更高的行高和上下留白获得仪式感：总高度约为普通弹幕的 `1.30–1.40` 倍。
- 新消息出现时不得引起已有条目横向跳动或宽度重排。

### 1.3 信息层级

从高到低固定为：

1. 弹幕正文或礼物名称/数量。
2. 用户名。
3. 身份、陪伴时长、礼物人民币价值等元数据。
4. 时间戳和装饰性状态文本。

建议基线（允许随输出缩放等比调整）：

| 元素 | 建议字号 | 字重 | 说明 |
| --- | ---: | ---: | --- |
| 正文/礼物主体 | `30–34px` | `600` | 最大、最清晰 |
| 用户名 | `18–20px` | `550–600` | 次级重点 |
| 身份/陪伴/价值 | `14–16px` | `450–500` | 不抢正文 |
| 时间/装饰状态 | `12–13px` | `400–450` | 右下角或边角 |

### 1.3.1 四套皮肤默认设置基线

皮肤设置必须按皮肤分别保存，互不共享；输出窗口的尺寸和位置由桌面窗口统一保存。当前锁定默认值如下：

| 皮肤 | 整体比例 | 垂直间距 | 正文 | 用户名 | 元数据 | 时间 | 字体 | 承载面不透明度 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| 轻雾玻璃 | `82%` | `8px` | `30px` | `18px` | `13px` | `12px` | `Microsoft YaHei UI` | `10%` |
| 单色点阵 | `100%` | `8px` | `32px` | `18px` | `14px` | `14px` | `GNU Unifont 16 Bitmap` | `100%` |
| OpenCode TUI | `88%` | `8px` | `32px` | `19px` | `14px` | `12px` | `JetBrains Maple Mono` | `94%` |
| Risograph | `86%` | `4px` | `34px` | `20px` | `15px` | `12px` | `KaiTi` | `100%` |

- 时间戳固定在当前条目的右下角，不建立独立时间列。
- 相同字段在不同身份之间必须使用完全相同的字号、字重、行高和间距。
- 禁止用更大字号表示主播、房管或舰队等级。

### 1.4 身份表达

必须明确区分：`主播`、`房管`、`总督`、`提督`、`舰长`、`普通观众`。

- 身份差异只通过明确文字标签、克制的语义色和小型符号表达。
- 标签采用 `[主播]`、`[房管]`、`[总督]`、`[提督]`、`[舰长]`；普通观众标签可隐藏，但数据结构中仍保留。
- 不改变对应字段的字号、字重或整体宽度。
- 颜色必须保证在动态游戏画面上仍可辨识；正文始终优先使用高对比中性色。

建议语义色：

| 身份 | 基础语义色 |
| --- | --- |
| 主播 | 克制珊瑚粉 |
| 房管 | 冷蓝/青蓝 |
| 总督 | 珊瑚红 |
| 提督 | 低饱和紫 |
| 舰长 | 天青/浅蓝 |
| 普通观众 | 中性白或皮肤主墨色 |

每套皮肤可以把这些语义映射到自己的有限色板，但不能依赖颜色作为唯一标识。

### 1.5 礼物与 SC

- 礼物条与普通弹幕严格等宽，内容居中，内部仍维持清晰的名称—动作—数量层级。
- 礼物金额只读取既有协议和金额换算结果；UI 不引入新的换算逻辑或可配置比例。
- 人民币统一格式为 `￥ 30.00`，保留两位小数。
- SC 也保持同宽，通过更高行高、置顶时长、色彩或局部材质区分，不改变宽度。
- 礼物和 SC 不得导致列表横向抖动。

### 1.6 动效

- 新消息：`160–220ms` 的轻微上移与淡入，水平位移为 `0`。
- 礼物：允许 `220–320ms` 的局部亮度/墨色增强，不允许整卡缩放弹跳。
- SC 置顶：只改变纵向位置和层级，宽度保持不变。
- 所有皮肤尊重系统“减少动态效果”设置。

## 2. 轻雾玻璃 `light-fog-glass`

### 视觉目标

几乎透明、冷调、局部轻雾。材质只负责保证文字可读，不应被观众先注意到。

### 材质

- 无边框、无侧边彩条、无应用级磨砂。
- 条目使用同宽的局部冷色雾层；基础透明度建议 `0.05–0.10`。
- `backdrop-filter: blur(18px) saturate(110%)` 可作为起点，最终强度由用户调节。
- 圆角 `8–12px`，禁止过度药丸化。
- 阴影只允许极弱的黑色环境阴影，不能形成悬浮卡片感。
- 色温保持中性偏冷；禁止暖金、米黄或浓厚奶油色雾层。

### 排版与颜色

- 推荐字体：`MiSans, HarmonyOS Sans SC, Microsoft YaHei UI, sans-serif`。
- 正文近白；用户名使用低饱和身份色；元数据为冷灰。
- 礼物主体可使用低饱和灰粉，但“赠送”等动作词保持近白。
- 普通内容左对齐；礼物在同宽雾层内居中且增加垂直留白。

## 3. 单色像素矩阵 `mono-pixel-matrix`

### 视觉目标

像精密的单色 LED 信息屏，而不是带背景点阵的复古滤镜。

### 像素规则

- 只渲染组成字形和符号的点亮像素。
- 未点亮像素必须 `display: none` 或 alpha 为 `0`，不得显示幽灵点、暗点、底层点阵或矩形网格。
- 全皮肤只使用一种琥珀色，建议 `#F2B93B`；紧贴像素的微弱光晕不超过 `1px`。
- 禁止第二强调色、渐变、玻璃卡片、边框和背景矩阵。

### 排版

- 文字必须直接读取真正的 CJK 位图字模（当前为内置 GNU Unifont 的 16×16 BDF 数据），禁止把普通矢量字体经过阈值、网格或滤镜伪装成像素字体。
- Canvas 可以逐位重放 BDF 的亮灭数据；直播间表情应提取透明轮廓及内部强边缘后再点阵化，不得把整张图片做满幅灰度噪点抖动，也不得从普通字体的抗锯齿轮廓反推字形点阵。
- 主要弹幕采用带一物理像素暗缝的疏点阵；小号名字、身份和时间在空间不足时允许退化为连续 1px 位图，不能为了保留暗缝而把 Canvas 画出其布局框。
- 输出窗口变宽主要增加每行容量。响应式字号只作轻微光学校正（`90%–112%`），禁止按窗口宽度线性放大。
- 各身份的用户名、标签和正文分别保持统一字号、字重、点密度和亮度。
- 身份只通过单色小符号和 `[身份]` 标签区分。
- 所有条目共用同一个不可见等宽布局框；礼物内容居中并增加行高，但点阵区域不缩窄。

## 4. OpenCode TUI `opencode-tui`

### 视觉目标

参考真实 OpenCode 左侧界面：纯黑、平面、信息密度高，依靠排版、留白和少量终端色建立层级。明确排除暖棕透明 Kitty 终端风格。

### 字体与表面

- 首选：`JetBrains Maple Mono`。
- 回退：`Maple Mono NF CN, JetBrains Mono, Noto Sans Mono CJK SC, Microsoft YaHei UI, monospace`。
- 条目为中性黑/炭黑哑光表面，建议 `rgba(10, 10, 10, 0.92–0.96)`。
- 圆角 `2–4px`；无边框、无阴影、无磨砂。
- 主文字 `#F3F1EE`，元数据 `#9B9998`，状态橙 `#F1A431`，动作蓝 `#4FA8F5`，成功绿 `#76D88F`，礼物/主播珊瑚 `#EE8D96`。

### `Thought` 行

`+ Thought: xxx` 保留，但重新定义为“当前弹幕与上一条已接收弹幕之间的时间差”，纯属显示层信息。

- `< 1s`：显示整数毫秒，如 `+ Thought: 451ms`。
- `1s–59.9s`：显示最多一位小数，如 `+ Thought: 1.8s`；整数秒可显示 `12s`。
- `>= 60s`：显示 `1m 10s`。
- 第一条消息没有上一条记录时隐藏该行。
- 计算不得参与协议解析、排序或重连判断，不能延迟消息处理。

### 礼物身份与价值行

- 删除模型和构建语义；不得显示 `Build`、`DeepSeek V4 Flash` 或推理耗时。
- 用户名、身份与礼物价值必须位于同一行，例如：`云水之间 [舰长]    ▣ Gift · ￥ 30.00`。
- 使用 OpenCode 动作语义展示现有换算结果：`▣ Gift · ￥ 30.00`，但不得单独占用一行。
- 金额行为是正文的辅助信息，字号不超过用户名。
- 下一行只展示主要礼物信息：`赠送  小花花 × 10`。
- 礼物条与普通条同宽，内部整体居中，总高度约为普通条的 `1.35` 倍。

## 5. Risograph `risograph`

### 视觉目标

真实双色孔版印刷，而不是“米色纸张 + 手写字体”。材质必须清楚呈现网点、套色误差和油墨不均。

### 纸张与油墨

- 纸张完全不透明，建议底色 `#E8DDC5`；游戏画面不能透过纸条。
- 固定两种专色：群青/钴蓝 `#123B8F` 与荧光珊瑚红 `#E95562`。
- 两印版允许 `2–4px` 的可见错位；红色底版应在蓝色字形边缘露出。
- 双色叠印区域使用 `multiply` 形成自然深紫第三色，不能额外引入第三种油墨。
- 大色块和角落必须看见粗网点；建议点径 `1.5–2.5px`、间距 `7–12px`，并加入轻微随机缺墨。
- 保留纸纤维、针孔、滚筒条纹、断边和油墨扩散；禁止干净矢量边缘。

### 几何与排版

- 所有纸条保持同一固定宽度和统一左右边界；只允许边缘有细微手工裁切误差。
- 禁止把礼物做成窄票据。礼物纸条同宽、内容居中、行高提升约 `35%`。
- 可以使用同色裁切标记、套准十字和粗糙下划线，但不能演变为贴纸拼贴或手账风。
- 正文为粗粝的中文展示字，元数据使用紧凑印刷黑体/等宽体；字段层级仍遵循全局规则。

## 6. 实现与验收清单

- OBS 画布外部完全透明，没有窗口或设置面板轮廓。
- 四套皮肤切换只改变视觉 token，不改变协议、排序、身份识别和金额逻辑。
- 普通弹幕、礼物和 SC 的外部宽度完全一致。
- 礼物只通过内容居中与更高行高区分。
- 正文永远比用户名大；用户名永远比元数据醒目。
- 不同身份的对应字段字号和字重完全一致。
- 时间位于条目右下角，不形成高注意力时间列。
- 点阵皮肤不存在任何未点亮像素。
- TUI 不含模型名或 Build 文案；用户名/身份与 `￥` 总价同行。
- Risograph 能肉眼看见网点、双色套印错位、叠印紫与不均匀墨色。
- 皮肤切换、消息到达和礼物出现时不发生横向跳动。
