## 检查范围

本轮逐段检查消息协议、礼物和上舰金额、SC、进房头像、表情、消息队列、九套皮肤、桌面／OBS同步、图片加载与缓存、设置／预设保存、扫码登录、窗口生命周期和安装包。针对可疑路径构造失败场景，再验证修复；验证使用独立配置、模拟上游、临时端口及隐藏 Electron 窗口。

## 已修复的问题

| 范围 | 触发条件和原有问题 | 修正行为 |
| --- | --- | --- |
| SC 重复／撤回 | 同一来源 ID 重送会生成多张卡片；上游撤回未删除 | 原卡片更新且保留初收时间；撤回清理消息、计时器和通知；删除先到及重复重送均处理 |
| SC 金额缺失 | 缺失或无效金额按零处理，可能仅显示5秒 | 保留未知金额，使用已有60秒默认时长 |
| 清屏时序 | 旧清屏 IPC 晚于新场景到达，误删较新的 SC | 清屏前比较版本，忽略旧通知 |
| 连接时序 | 切房后旧 socket 回调、重连定时器仍可能影响新连接 | 按连接代次和 socket 身份隔离；断开清理旧队列与计时器 |
| 网络停滞 | API、TLS／升级／认证无回复时可一直停在连接中 | API 8秒超时；连接认证35秒超时后按原机制恢复 |
| 解码与异常元数据 | 慢解包时待处理闭包增长，超大压缩展开或深层表情可拖垮处理 | 队列、展开字节及嵌套深度有上界；异常元数据不再递归溢出拖掉普通消息 |
| 头像恢复 | 一次查询失败在服务端缓存6小时、渲染端可能永久命中空结果 | 失败缓存15秒；成功缓存6小时；显式消息头像优先 |
| 图片资源 | 同图重复下载，下载完整数据后才判断超限，隐藏后请求继续占用 | 合并同源请求；流式超限立即取消；隐藏／关闭头像取消请求并释放元素 |
| 设置持久化 | 普通写入可截断旧文件；SC设置未落盘就触发不可逆过期 | 所有保存采用临时文件原子替换；成功落盘后才应用设置，失败回滚 |
| 登录流程 | 二维码请求乱序、隐藏后轮询、慢轮询重叠、旧账号状态覆盖 | 按登录会话取消旧请求，轮询串行，旧响应不得改变新状态 |
| 登录凭据 | 客户端已关闭／退出，旧服务端请求仍可能写回登录态 | 服务端校验二维码代次、请求状态和候选账号；凭据原子保存，失败不误报成功 |
| 控制台交互 | 初始化旧快照覆盖新开关／尺寸／穿透操作；复制提示卡住；弹窗键盘焦点可落到背后 | 保护较新状态；复制反馈复位；弹窗移焦、Tab约束和Esc返回 |
| 本机资源接口 | 静态服务可能读取配置文件；跨站页面可能发起本机状态操作 | 只提供界面资源；移除任意站点的读取许可，限制跨站登录和WebSocket操作；拥塞保留503状态 |

## 验证限制与保留行为

- 开启“SC不自动消失”时，SC历史按用户选择持续保留，没有数量上限；因此长期积累会增加占用。本轮没有为节省内存擅自丢弃付费留言。
- 数值边界和隐藏窗口测试不等于低配笔记本的实际CPU／内存测量；本轮未在朋友的Win10机器上实测。
- 本轮没有重新进行原生拖动、鼠标穿透命中或Windows通知中心点击验收。模拟事件与隐藏DOM检查不被当成原生输入测试。
- 无法从代码测试追溯未保留原始消息的历史漏收，也不能保证B站未来不再调整格式；运行时SC诊断用于区分后续的接收、解析、发布、过期和移除阶段。
- 安装包验证包括构建成功、外层与嵌入压缩完整性、打包源码一致性及测试／旧点阵资源排除；未在真实用户配置上执行自动安装或卸载。

## 0.8.15 追加：SC 下架回到弹幕流
