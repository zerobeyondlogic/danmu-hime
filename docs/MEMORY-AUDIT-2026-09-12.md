# 长时间运行与内存回收检查

检查日期：2026-09-12。基线为0.8.15，修正候选为0.8.16。所有压力测试使用独立配置、模拟消息和本地资源；未操作用户直播间、OBS或桌面输入。

## 已确认的问题与修正

旧网页 `/relay` WebSocket 通道此前未限制慢客户端的待发送缓冲，客户端停止读取后还会不断堆数据；模拟100条64KiB消息已累积6,564,456字节。该问题发生于旧网页通道，当前桌面／OBS的SSE通道已有1MiB背压保护。

修正后旧网页客户端也有1MiB背压保护，超过后断开该连接；健康客户端和内部桌面订阅继续收到全部实时消息，单次 `write(false)` 不直接触发断开。

中继回放缓存此前只有48条限制，没有总字节限制。48条含512KiB正文的模拟消息可保留25,165,910个序列化字符。大消息仍需要实时交付，但无需无限保留给后来加入的旧网页客户端。

修正后回放同时受48条和8MiB原始编码字节约束，使用解码帧已有的长度，避免额外序列化。单条超预算仍实时交付，只不保留用于旧网页回放；后续正常消息仍可回放。此预算不是JavaScript堆占用的精确大小。

房间表情缓存此前只限制32个房间，单房条目数量与字段长度没有相应限制；客户端实际只使用前1024项。模拟单房2500项时，服务端会长期保留全部2500项。

修正后每房最多1024项、名称最多120字符、URL最多2048字符，最多扫描4096个候选；同时以32个房间和8MiB序列化UTF-16估算字节限制缓存。只裁掉客户端本来就不使用的额外内容，不改变正常表情显示大小。

## 实际Electron持续测试

0.8.15界面与消息链的独立副本实跑602.453秒，处理32,172条模拟消息。三个90秒负载阶段目标约120条/秒，各阶段切换全部九套皮肤，再清空、闲置和采样；桌面输出重建9次，控制台重建3次，OBS镜像页始终使用同一进程。SC覆盖自然到期，手动下架／撤回由独立功能回归覆盖，没有把它们计入本次长测。

三个界面均为隐藏离屏窗口，仅测试副本关闭后台降速，使用本地SVG头像／礼物／表情。分别记录垃圾回收前后V8堆、DOM与监听器、资源队列和Electron进程指标。GC只作用于隔离页，不清空系统工作集。测试未发现界面错误、崩溃或自重启；结束后18个采样到的测试PID均已退出，本地17800端口关闭。

整组测试进程包含控制台、桌面和额外OBS镜像，重建后每轮末尾私有提交内存合计约450.13／453.78／441.78MiB。这些数值用于同条件趋势比较，不是用户当前仅OBS使用时弹幕姬的实际总占用；进程重建也不能用于证明不重建时原生资源会自行回落。本轮尚未做真实可见界面连续整夜、不重建窗口的GPU测量。

## 重启与风险边界

- 源码未设置周期性应用重启或 `app.relaunch()`。退出路径来自用户退出、重复启动时第二个实例退出、启动失败，以及没有托盘时关闭所有窗口。断线重连和OBS检测到新版本后重载页面是独立行为。
- 本机Application日志可读取，最近14天未找到与弹幕姬匹配的崩溃／无响应记录；这不能排除未记录的进程终止。检查开始时没有正在运行的弹幕姬正式进程。
- “SC永久置顶”会持续保留尚未下架的SC，这是内容保留而非遗失引用。自动模式也要保留仍在置顶时长内的SC；到达越频繁、金额对应时长越长，活跃内容越多。没有为降低内存擅自删除付费留言或修改时长。
- 只读检查本机当前保存的配置：使用轻雾玻璃，SC永久置顶关闭，桌面预览关闭；未修改任何用户配置或登录状态。
- JavaScript堆、Electron进程私有提交内存和工作集是不同指标。图片、字体、GPU及浏览器分配器会预热缓存，任务管理器数字没有立刻降回初值不能单独证明泄漏。离屏测试值也不能当作真实桌面常态占用。
- 模拟6小时验证的是计时及数据结构回收；实际持续测试的墙钟时间另行记录，不能把模拟时长当作真实运行时长，更不能据此保证所有机器连续运行数天都无异常。
