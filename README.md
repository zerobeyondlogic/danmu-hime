# Danmu Hime（弹幕姬）

![Danmu Hime 图标](desktop/assets/icon.png)

面向 Bilibili 主播的 Windows 桌面弹幕工具。主播预览窗口是唯一的布局基准，OBS 浏览器源实时镜像同一场景、尺寸与皮肤设置。

> 当前版本：`0.3.0`。项目仍在迭代，发布包暂未进行代码签名，Windows SmartScreen 可能显示未知发布者。更新内容见 [变更记录](CHANGELOG.md)。

## 主要功能

- 透明、可缩放的主播桌面预览，拖到显示器边缘时自动吸附
- 可锁定预览窗口尺寸，锁定后仍能自由拖动位置
- OBS 浏览器源与桌面预览共享同一场景，不再各自重新排版
- 轻雾玻璃、单色点阵、OpenCode TUI、Risograph 四套皮肤
- 每套皮肤可独立调整字体、字号、间距、颜色、缩放、承载面透明度与头像显示
- 显示头像时自动补偿窗口宽度，关闭头像后恢复
- 普通弹幕、礼物、上舰和 SC（醒目留言）展示
- SC 持续置顶，主播在预览窗口中将对应卡片滑走后消失
- 主播、房管、总督、提督、舰长身份样式
- 可选窗口置顶、鼠标穿透，以及 `Ctrl + Shift + F10` 快速解除穿透
- B 站扫码登录，用于获得完整用户名和登录态接口能力
- 关闭控制台时可选择退出或收起到系统托盘；收起后释放设置窗口，弹幕接收和 OBS 输出继续运行
- 关闭桌面预览会释放预览窗口；消息由主进程处理，只有托盘时仍可向 OBS 输出
- 点阵脚本和字库在首次进入点阵皮肤时加载，仅为可见卡片分配画布，离屏后释放

## 下载与使用

推荐使用 Windows x64 安装版 `Danmu-Hime-0.3.0-Setup.exe`，安装后从桌面快捷方式或开始菜单打开。程序文件只在安装或升级时解压，之后启动无需重复解压，可减少便携版每次打开前的等待。

升级或从便携版切换前，请先从托盘菜单选择“退出弹幕姬”，完全退出旧版。同一 Windows 用户下会沿用原来的设置和 B 站登录态。

1. 输入直播间房间号并连接。
2. 按需要选择皮肤、调整输出窗口并决定是否锁定尺寸。
3. 在 OBS 中添加“浏览器”源。
4. URL 填写控制台显示的地址，默认是：

   ```text
   http://127.0.0.1:38426/desktop/overlay.html?mode=obs
   ```

5. 将 OBS 浏览器源的宽高设置成控制台显示的主播预览窗口尺寸。首次运行默认是 `450 × 650`。

OBS 页面仅包含透明弹幕画布，不会捕捉控制台、窗口边框或桌面拖动手柄。关闭“显示主播桌面预览”会释放桌面预览窗口，不会中断 OBS 输出；仍可在控制台修改输出宽高和皮肤。重新开启后按保存的尺寸恢复，并显示当前弹幕及置顶 SC。

点击控制台右上角的关闭按钮，或按 `Alt + F4`，可选择“收起到托盘”“退出程序”或“取消”。收起会保存设置并释放控制台窗口；桌面弹幕预览和 OBS 输出仍按原设置运行。点击任务栏右下角的弹幕姬图标，或右键选择“打开控制台”，即可恢复设置窗口；右键菜单中的“退出弹幕姬”会结束整个程序。普通最小化按钮仍将窗口最小化到任务栏。

## 尺寸与 Windows 缩放

控制台显示的是预览窗口内部的逻辑尺寸，不包括 Windows 窗口阴影和不可见边框。Windows 的 100%、150% 等显示缩放会影响桌面上的物理大小，但 OBS 仍按控制台给出的逻辑宽高渲染。要让两边一一对应，请让 OBS 浏览器源使用相同的宽高，并避免在 OBS 中对源做非整数比例的二次缩放。

## 本地开发

需要 Node.js 18 或更高版本。

```powershell
npm ci
npm run desktop
```

常用命令：

```powershell
npm run check          # JavaScript 语法检查
npm test               # 协议、连接、表情、头像和点阵字体测试
npm run dist           # 生成 Windows x64 安装版 EXE
npm run dist:portable  # 生成 Windows x64 便携版 EXE
```

构建产物按版本保存在 `dist/<版本号>/`，本次安装包为 `dist/0.3.0/Danmu-Hime-0.3.0-Setup.exe`。旧版本产物保留在原目录。

### 版本维护

交付内容有变化时递增版本号；同一内容的安装版和便携版共享版本号。后续小修复可先运行以下命令，再同步本文版本、安装包文件名及 [变更记录](CHANGELOG.md)，最后检查、测试和打包：

```powershell
npm version patch --no-git-tag-version
```

此命令只更新 `package.json` 和锁文件。用户确认版本后，完成版本号与变更记录同步、检查、测试和打包，将对应改动提交并正常推送到当前分支的跟踪远端，同时创建并推送 `v<版本号>` 标签。这是持续授权，无需再次询问是否推送；普通开发改动不自动视为已确认版本。

不强制推送，不改写已有版本标签；凭据、本地状态和构建产物不提交到 Git。此流程同步 Git 分支和标签，不自动创建 GitHub Release 或上传安装包。

## 隐私与本地数据

- B 站扫码登录产生的 Cookie 只保存在本机应用数据目录的 `data/cookies.json`。
- 房间号、窗口位置、皮肤等设置保存在本机的 `desktop-state.json`。
- `data/`、构建目录和临时文件已被 Git 忽略，不会提交到仓库。
- 请勿分享 `cookies.json`；它包含你的 B 站登录凭据。退出登录会清除应用使用的登录态。

## 常见问题

**连接后没有弹幕**

先确认直播间房间号有效。程序重启后如果控制台仅显示已保存但实际未连接，点击“重新连接”。网络中断时中继会自动尝试恢复。

**OBS 四周有透明空白**

检查 OBS 浏览器源宽高是否与控制台一致，并在“变换”中重置源，避免遗留裁剪、边界框或非等比缩放。

**OBS 字体发糊**

优先使用与场景匹配的浏览器源分辨率，并在 OBS 内按整数比例显示。先缩小浏览器源再放大，会把已经栅格化的文字一并放大。

**桌面预览无法拉伸**

关闭“锁定输出窗口尺寸”。如果只看到位置变化而画面没有重排，先确认运行的是最新 Release。
